## Licenses, terms and access policy

- [NWS API policy](https://www.weather.gov/documentation/services-web-api): U.S. government open data free for use with reasonable undisclosed rate limits; NWS requests an identifying `User-Agent`. A browser cannot reliably set an arbitrary forbidden `User-Agent` header, so production-scale polling may require a well-identified low-rate caching proxy. Do not embed secrets in static builds.
- [NOAA NODD](https://www.noaa.gov/information-technology/open-data-dissemination): NOAA data are openly distributed; dataset pages request attribution and prohibit implying NOAA endorsement or claiming modified data are unaltered. Data availability/free access does **not** make processing, egress, object hosting or basemap bandwidth free.
- SPC FeatureServer metadata and underlying SPC forecast products are official; explicit API rate limits, uninterrupted CORS/browser access and exact observed GIS publication delays **not confirmed**. Validate against upstream service terms.
- Sounding portals, non-NOAA mesonets and possible third-party vector/basemap tiles have different usage constraints; seek specific redistribution permission/license before bundling or mirroring data.

## Cost and architecture decision gates

1. **v0.1:** static React app on GitHub Pages; no paid server, database, scheduled compute or custom commercial data source is required by present design. Check [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits): published site 1 GB maximum and *soft* 100 GB/month bandwidth limit. Live weather APIs and tiles remain upstream dependencies.
2. **Low-volume v0.2–0.3:** start with regional GRIB field subsetting + scheduled server-side conversion and immutable compact assets. Avoid full nationwide HRRR/ensemble fields downloaded by every browser client. Use hourly caching, request deduplication, range reads, gzip/COG/vector tiles where suitable and backoff. NOMADS recommends [at least 10 seconds between looped GRIB Filter requests](https://nomads.ncep.noaa.gov/info.php?page=gribfilter).
3. **Future object storage:** consider [Cloudflare R2](https://developers.cloudflare.com/r2/pricing/) (Standard: 10 GB-month, 1M Class A, 10M Class B free monthly; beyond free: listed rate $0.015/GB-month, $4.50/M Class A, $0.36/M Class B at this research date). This is *not* a selected provider or cost guarantee. Compare storage, ingest, egress, compute, cache purges, observability and reliability before adoption.
4. **No cost projection without workload:** benchmark bytes per requested field, domain fraction, hourly/daily retention, conversion CPU/RAM, tile count, API reads, active users and cache hit rate. Test one representative severe-weather day, then multiply measured resource usage by current provider prices. Set budgets, alerts, per-source download caps and product TTLs.
5. GitHub Actions scheduled jobs may be delayed and are not an appropriate sole source of safety-critical live feeds. Future ingest should use independent retries, health metrics, and a provider-failure/stale status rather than a silent successful last image.

## Highest-value scientific progression

1. Verify v0.1 polygon provenance, NWS alert identity and live API behavior.
2. Add source metadata/health UI and official SPC probabilistic/CIG fields with correct distinct meaning.
3. Add a controlled RAP/HRRR single-domain pilot with **same valid-time, different run** trends; prove GRIB variable definitions and no look-ahead.
4. Extend to model vertical profiles; implement MetPy with documented parcel assumptions, 0–1/0–3 km SRH, Bunkers motion, LCL/LFC/EL, CAPE/CIN and hodographs; benchmark profile/derived fields against authoritative sounding diagnostics.
5. Expand to ensemble summaries, radar/MRMS, satellite and observations after throughput, quality, timestamp and costs are measured.
